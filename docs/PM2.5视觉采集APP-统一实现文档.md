## 1. 产品目标与交付边界

### 1.1 产品定位

PM2.5 视觉采集记录仪用于实验室固定机位场景：摄像头拍摄多台净化器、除湿机等设备的屏幕，系统按配置周期从真实视频帧中裁剪 ROI，离线识别 PM2.5 数值并进行本地记录、监控、复核和导出。

### 1.2 业务目标

- 使用 Android 手机后置摄像头完成真实采集。
- 使用 Windows 电脑连接指定 UVC 摄像头完成真实采集。
- 让操作人员能够建立测试批次、配置多个设备屏幕 ROI、启动和停止采集。
- 让每个 ROI 的识别结果可追踪到批次、设备、时间、模型版本和采样周期。
- 在无网络条件下完成采集、存储、复核和 CSV 导出。
- 通过真机和真实摄像头数据验证识别质量、性能和长期稳定性。

### 1.3 本期正式交付范围

#### Android 必须交付并验收

- 批次管理。
- ROI 绘制、移动、缩放、删除、模板保存和模板加载。
- 每个批次 1–8 个 ROI。
- ROI 设备编号唯一、坐标合法、模型输入有效。
- Android CameraX 真实相机预览和取帧。
- 竖屏、横屏、相机旋转、镜像、裁剪和触摸映射。
- AF/AE 触发、收敛、锁定和状态确认。
- 随安装包提供或通过离线安装落地的真实数字 REC 模型、字典、配置和推理运行库。
- 真实相机帧到 ROI 裁剪、推理、解析、记录、曲线、回放和 CSV 的完整链路。
- 实时监控、暂停/继续、停止、识别失败展示、人工修正和备注。
- 本地日志、异常处理、批次恢复和存储空间检查。
- 真实 Android 设备上的功能、性能和稳定性验收。

#### Windows 必须交付并验收

- 指定 Windows PC 和指定 UVC 摄像头的真实采集。
- 摄像头型号、分辨率、帧格式、采集后端和驱动组合锁定。
- 与 Android 共用批次、ROI、记录、曲线、回放、复核和导出业务。
- Windows 端真实模型加载和识别链路验证。
- UVC 摄像头断开、重连、能力不足和不支持状态的明确反馈。

### 1.4 本期明确不包含

- iOS、Linux、macOS 平台。
- YOLO 或其他自动目标检测。
- 视频录制。
- 云端同步、账号体系、多账号数据流转。
- MVP 阶段的内网实时上传和网络请求。
- 使用演示数据、固定结果、模拟帧、离线图片回放替代真实验收。

### 1.5 交付原则

1. 真机是真实功能的唯一验收路径，模拟器和桌面原型不能替代 Android 验收。
2. 真实模型缺失、加载失败或输出异常时，禁止启动正式采集。
3. AF/AE 无法确认锁定时，不得显示“已锁定”，也不得使用演示数据继续采集。
4. 每个合法 ROI 都必须进入识别、记录、复核和导出链路，不得静默跳过。
5. 低性能设备不得静默降低采样频率或识别质量；只能采用已验证并由用户明确选择的较慢周期。
6. 性能指标是待实测门槛，不是当前已达成结果。

## 4. 功能实现规格

### 4.1 批次管理

#### 输入

- 批次编号。
- 项目名称。
- 测试人员。
- 备注信息，如风量、湿度、样品版本。
- 采样周期和当前相机/设备信息。

#### 状态

- `未开始`：可以编辑 ROI、加载模板和执行采集前检查。
- `采集中`：禁止改变 ROI 和 AF/AE 调优状态。
- `已停止`：进入回放、复核和导出。

#### 规则

- 默认批次编号格式为 `yyyyMMdd_HHmm`。
- 自动生成编号与已有编号冲突时追加递增后缀。
- 用户手动输入重复编号时，在对话框内提示并阻止保存。
- 打开逻辑：未开始进入 ROI 编辑；采集中进入实时监控；已停止进入回放。
- 删除批次前二次确认，并级联删除关联记录、日志和临时数据。
- 退出应用或异常关闭后，未正常结束的批次必须恢复为可回放/可安全停止状态，不得丢失已写入数据。

### 4.2 ROI 管理

#### 数据

每个 ROI 至少保存：

- 设备编号。
- 归一化坐标 `left/top/right/bottom`。
- 创建和更新时间。
- 所属批次或模板。
- 当前相机视口/方向版本信息，必要时记录裁剪映射版本。

#### 规则

- ROI 数量必须为 1–8；第 9 个必须阻止新增或导入。
- 坐标必须满足 `0 ≤ left < right ≤ 1`、`0 ≤ top < bottom ≤ 1`。
- 裁剪到当前帧后宽度和高度必须大于 0，并满足模型最小输入要求。
- 同一批次内设备编号不重复，比较时忽略首尾空格并统一大小写。
- 坐标越界、面积无效、编号重复或数量非法时禁止保存/启动，并指出具体修复项。
- 模板加载后必须重新校验，不能因为模板历史合法而跳过当前相机/模型约束检查。
- 0 个 ROI 时禁止启动采集。
- 1、3、5、8 个 ROI 必须分别进入功能测试；8 个是功能硬上限和必测数量。

#### 交互

- 相机画面作为主要空间，ROI 控件叠加在预览边缘。
- 支持新增、拖动、四角缩放、删除、编号编辑和模板保存/加载。
- 竖屏和横屏下控件重新排列，但不改变 ROI 的业务坐标。
- 画面方向、触摸方向和 ROI 位置必须一致。

### 4.3 相机与坐标映射

#### 统一坐标链路

必须在实现中明确以下坐标空间：

1. 相机原始帧坐标。
2. CameraX/UVC 输出帧坐标。
3. ViewPort 裁剪坐标。
4. 预览组件显示坐标。
5. 屏幕触摸坐标。
6. ROI 归一化业务坐标。

所有转换必须经过同一份旋转、镜像、裁剪和缩放规则，不能在 UI 和原生层分别使用隐式变换。

#### 验证要求

- 竖屏预览不得横向压扁、拉伸或倒置。
- 手机向左/右移动时，触摸和画面空间方向必须符合用户直觉。
- 使用非对称数字靶标覆盖四角和不同方向验证坐标映射。
- 前后台切换、旋转、断开重连后重新核对预览和 ROI 对齐。
- 预览使用平台纹理/预览面；高频完整帧不得通过 MethodChannel 逐帧复制到 Dart。

### 4.4 AF/AE 调优与锁定

#### 默认流程

1. 打开相机并确认相机能力。
2. 用户手动触发“相机调优（ROI 优先）”。
3. 将选中的 ROI 中心转换为对焦/测光点；一台相机的曝光和焦点对整帧生效，不为 8 个 ROI 分别锁定。
4. 等待设备对焦、测光收敛。
5. 请求锁定 AF/AE。
6. 读取并确认锁定状态。
7. 将状态、时间和失败原因写入日志和批次验收信息。
8. Android 仅在分别确认 AF、AE 已锁定后允许采集；清晰度评分只能辅助判断。Windows UVC 若不公开锁定控制，只允许使用登记并通过画质验证的固定配置，界面不得称之为“已锁定”。

#### 规则

- 采集过程中禁止重新调优。
- 设备不支持、请求失败、状态未知或锁定丢失时不得伪报成功。
- EV 和手动对焦等入口只在设备能力允许时展示。
- AF/AE 状态必须区分“未触发、调优中、已锁定、失败、不支持、未知”。
- Android 无法确认 AF/AE 锁定的设备不能列入已验收支持清单。

### 4.5 模型管理与 OCR 识别

#### 必须交付的模型资产

- 数字 REC 权重。
- 匹配字典/标签。
- 预处理和后处理配置。
- Android/Windows 对应推理运行库。
- 模型版本、格式、输入输出契约和 SHA-256。

#### 安装规则

- 模型随安装包提供，或通过离线安装落到应用受控目录。
- 禁止运行时联网下载。
- 安装后必须检查文件完整性并记录版本/哈希。
- 模型缺失、哈希错误、加载失败或输入输出不匹配时阻止正式采集。
- 不得使用固定结果、模拟模型或未满足契约的通用 PP-OCR 模型替代目标数字 REC 模型。

#### 识别输出

每个 ROI 至少产生：

- 设备编号。
- 采样计划时间和实际时间。
- 原始识别文本或数值。
- 解析后的 PM2.5 数值。
- 置信度。
- 识别状态：成功、低置信度、无效、超时、异常、丢帧。
- 模型版本和配置标识。

默认 `confidence ≥ 0.85` 且数值合法时正常入库；`0.60 ≤ confidence < 0.85` 时保留有效候选值并标记待复核；低于 `0.60`、文本无法解析、无帧或超时时不写有效数值，保留对应失败状态及原因。阈值须用带真值样本校准，不把模型置信度当作准确率。

模型接口在选型验证后锁定，包括输入张量形状、颜色/归一化、字典与解码方式。现有单 ROI CTC 探针契约仅作为兼容候选，不是正式模型已选定的依据。安装流程应自动放置资产，不依赖用户手动复制。

### 4.6 采集调度

- 默认周期为 1000 ms。
- 允许 2000/5000 ms，但只有经过目标设备验证并由用户明确选择后才能使用。
- 单轮截止时间为所选周期的 80%。
- 单飞执行：上一轮未结束时不并发启动下一轮。
- 逾期结果不写入有效数值，并记录丢帧/超时。
- 使用单调时钟固定计划拍点，不补采错过的节拍；超时废弃整轮的有效值，迟到结果不得回写。未跑完的 ROI 必须可在失败状态中追踪。
- 每轮必须遍历全部 ROI，不得为满足节拍而静默跳过 ROI。
- 暂停保留批次和已提交记录，继续前重新检查帧、锁定、模型与存储；停止后不再写入或继续同一批次。Android 切到后台沿用当前安全停止策略；采集中相机断流或锁定失效时告警并安全停止，重连和重新确认后以新批次采集。
- 低性能设备必须显示实际采样周期、ROI 数量和性能状态。

### 4.7 实时监控

#### 信息层级

1. 实时曲线和当前数据变化。
2. 批次状态、采样周期、模型和相机状态。
3. 设备读数卡片、置信度和失败状态。
4. 主要操作。
5. 记录表和更多操作。

#### 交互

- 曲线置于监控内容顶部。
- 支持曲线全屏查看和明确退出。
- 全屏前后保持同一批次、数据序列和时间范围。
- 暂停/继续、停止批次、更多组成居中操作组。
- 记录表独立展开/收起，不与曲线入口重复。
- 颜色不是唯一状态表达方式，失败和告警必须同时有文字或图标。

### 4.8 人工复核、回放与导出

- 支持按批次、设备、时间和状态筛选。
- 原始值和人工修正值分开保存。
- 修正必须保存操作时间、操作者信息（如当前版本无账号则保存本地操作标识）和备注。
- 历史曲线不对缺失数据进行虚假插值。
- CSV 使用 UTF-8 BOM，字段至少包含批次、设备、时间、原始值、修正值、置信度、状态、备注、模型版本、采样周期和 ROI 标识。
- 保留基础 CSV 字段及顺序：`timestamp_ms, scheduled_at_ms, actual_interval_ms, time_str, batch_id, device_id, pm25_value, confidence, is_manual_modify, remark, status`；`status` 为 `normal / review / failed`，扩展字段追加在末尾。按原始值与人工修正值分别记录，不覆盖原始值。
- 支持单独导出失败/丢帧日志；Android 通过系统文件选择器保存，Windows 通过系统保存对话框保存。
- 导出失败时保留明确错误，不删除本地数据。

### 4.9 系统配置（F10）

| 分组 | 本期行为与默认值 |
|---|---|
| 识别/告警 | 高低置信阈值默认 0.85/0.60；告警上限和下限按项目设置 |
| 采样/曲线 | 默认 1000 ms；仅提供已验证的 2000/5000 ms 慢周期；曲线默认窗口 300 秒 |
| 快照 | 可选失败快照，默认关闭；启用后纳入存储空间检查和长时压测 |
| 相机调优 | ROI 变化后自动调优默认关闭；超时初始值 2000 ms，清晰度阈值须随真实样本和相机模式校准 |
| 上传预埋 | 开关关闭且不可开启、地址默认空、间隔默认 5 秒；不得产生请求、遥测或心跳 |

### 4.10 本地日志（F11）

按类别记录操作、识别失败、丢拍、相机/AF/AE、模型、存储和导出事件；至少包含事件时间、批次标识（如适用）与原因。丢拍日志保存计划拍点和耗时，OCR 失败日志可关联 ROI、置信度与可选快照。支持本地查询和清空日志，清空不得删除批次或测量记录。上传仅可记录预留配置状态。

## 5. 技术架构与代码结构目标

### 5.1 分层结构

后续实施应将工程逐步整理为以下职责边界：

```text
presentation/
  页面、组件、路由、设计令牌、状态展示
application/
  批次用例、ROI 用例、采集用例、回放/导出用例
domain/
  Batch、Roi、Reading、CaptureConfig、状态和校验规则
data/
  Drift/SQLite、配置、日志、模型资产元数据
platform/
  Android CameraX、Windows UVC、权限、AF/AE、平台状态
vision/
  帧裁剪、预处理、REC 推理、解析、置信度和结果映射
scheduling/
  采样周期、单飞、超时、丢帧、取消和恢复
```

当前工程可以继续渐进式重构，不要求一次性改名或大规模迁移；优先将高频帧、相机控制、推理调度和页面状态从页面文件中剥离。

### 5.2 平台适配原则

- Flutter 只接收控制结果、状态和识别结果。
- Android 使用 CameraX 原生能力处理帧、旋转、ViewPort、AF/AE 和纹理预览。
- Windows 锁定真实 UVC 采集后端、摄像头型号、模式和帧格式。
- 平台能力必须显式返回“支持/不支持/未知/失败”，不能通过默认值伪装成功。
- 图像处理和推理优先在原生或高效缓冲区路径完成，避免高频跨通道复制。

平台契约以一次采集为边界：控制输入是相机会话、带版本的视口状态、ROI 集合和截止时间；输出是帧时间、各 ROI 的原始识别结果/置信度或失败原因，以及会话/能力状态。会话关闭与失效时，忽略旧会话的回调；Flutter 不通过此接口接收完整帧。

### 5.3 模型管理器职责

- 检查模型文件和配置。
- 计算并校验 SHA-256。
- 读取输入尺寸、归一化参数、字典和输出契约。
- 初始化推理运行库。
- 报告版本、加载耗时和失败原因。
- 为每个批次记录使用的模型版本和配置。

### 5.4 数据一致性

批次、ROI、配置、记录和日志需要保持以下一致性：

- 批次删除时关联记录和日志可控级联。
- 开始采集时固定本批次 ROI、模型版本、周期和设备信息。
- 采集过程中不能修改影响解释数据的关键配置。
- 单轮识别和记录写入尽量在一个事务内完成。
- 应用异常退出后，已写入记录可回放，未完成轮次标记为失败或未完成，不生成虚假成功值。

## 6. 性能、稳定性与设备支持规则

### 6.1 性能测量维度

必须在 Android 真机和 Windows 指定环境中测量：

- 1、3、5、8 个 ROI。
- 1 秒默认周期及经过验证的慢周期。
- 单轮总耗时 P50/P95/P99。
- 推理耗时、预处理耗时、入库耗时和 UI 更新耗时。
- 丢帧/超时率。
- 识别准确率和低置信度比例。
- CPU、内存、温度、降频和电量变化。
- 连续 4 小时运行的崩溃、断流和数据完整性。

### 6.2 支持声明

| 指标 | A1.3 验收基线（非实测结果） |
|---|---|
| 单轮 P95 | ≤ 所选周期的 60%；1/2/5 秒档分别为 600/1200/3000 ms。硬截止为周期的 80%，分别为 800/1600/4000 ms |
| 丢拍率 | 每项支持配置连续 2 小时 < 1%；分母为计划拍点数；记录环境温度和降频情况 |
| 识别质量 | 良好光照、无明显反光时，自动接受读数的完整数值精确匹配率 ≥ 98%；同时报告覆盖率、待复核率、失败率；建议验证集至少 1000 条人工真值 ROI 样本，按设备和工况分层 |
| 长时稳定性 | 声明支持的组合连续真实采集 4 小时无崩溃、无异常断流，事务写入完整，重启后可复核 |
| 最低配置 | 每个平台至少一台最低目标设备在其声明配置下通过；8 ROI 必测，8 ROI 功能与 1Hz 性能单独判定 |
| 暂定体验目标 | 冷启动到可采集 ≤ 5 秒；1 小时、8 路批次回放打开 ≤ 2 秒、CSV 文件生成 ≤ 3 秒；2 小时内存涨幅 < 50 MB 为后续优化目标 |

以计划拍点和轮次结果作为记账依据；超时/跳拍计入丢拍率，不用成功轮次的耗时分位数掩盖失败。自动接受覆盖率应同时披露，不能通过大量拒绝样本只报精确匹配率。

只有满足对应配置的准确率、P95、丢帧和稳定性门槛，才能声明某设备支持该 ROI 数和采样周期。

设备支持清单至少记录：

- Android 设备型号和系统版本，或 Windows PC/OS。
- 摄像头型号、硬件 ID、分辨率、帧格式和采集后端。
- 模型版本、运行库版本和 SHA-256。
- ROI 数量、采样周期和推理线程配置。
- AF/AE 能力和锁定结果。
- 测试时间、真值样本、输出结果和结论。

### 6.3 低性能处理

- 不得静默降低识别质量。
- 不得未告知用户自动改变采样周期。
- 可以提供已验证的 2000/5000 ms 周期，但必须在界面显示并写入批次记录。
- 如果设备在 8 ROI 下只能支持更慢周期，应标记“8 ROI 功能支持、1Hz 不支持”，不能把功能失败和性能不支持混为一谈。

## 9. 异常与边界条件

| 场景 | 系统行为 |
|---|---|
| ROI 数量为 0 | 禁止启动，提示先创建 ROI |
| ROI 数量为 1–8 | 允许保存、校验和进入采集前检查 |
| ROI 超过 8 | 阻止新增/导入，提示最多 8 个 |
| 坐标越界或面积无效 | 禁止保存/启动，指出具体 ROI |
| 设备编号重复 | 禁止保存/启动，提示重复编号 |
| 相机权限未授予 | 不启动采集，引导授权或重试 |
| 相机无法打开/取帧中断 | 显示明确错误，提供重试和安全退出 |
| 预览方向或映射未知 | 禁止正式采集，要求重新初始化或报告失败 |
| AF/AE 不支持或无法确认 | 显示真实失败状态，禁止伪报成功 |
| 模型缺失/哈希错误/加载失败 | 阻止正式采集，显示模型问题 |
| 模型输出异常 | 记录失败，不伪造 PM2.5 数值 |
| 单轮超时 | 写入超时/丢帧状态，不写有效数值 |
| 单个 ROI 失败 | 记录该 ROI 失败，其他 ROI 按规则继续 |
| 本地空间不足 | 阻止开始或安全停止，并提示处理 |
| 应用异常退出 | 保留已写入数据，批次可恢复和回放 |
| 批次编号重复 | 对话框内提示，禁止保存 |
| 导出失败 | 保留原数据并提示原因，不生成误导性成功提示 |

## 10. 测试与验收矩阵

### 10.1 UI 和交互

- 首页说明区域不可误认为按钮。
- “建立测试”居中，底部无整条背景承载栏。
- 批次编号格式正确，同分钟重复自动后缀。
- 重复编号阻止保存并显示业务提示。
- ROI 预览在常见手机尺寸下可操作。
- 竖屏、横屏下控件不遮挡主要取景。
- 曲线在监控页顶部。
- 曲线可进入/退出全屏，数据连续。
- 操作组居中，记录表独立展开/收起。

### 10.2 ROI

- 0 个 ROI：禁止启动。
- 1 个 ROI：完整识别和记录。
- 3 个 ROI：完整识别和记录。
- 5 个 ROI：完整识别和记录。
- 8 个 ROI：全部进入识别、记录、回放和导出。
- 第 9 个 ROI：明确阻止。
- 非法坐标、重复编号和模板非法内容：明确阻止。

### 10.3 相机与方向

- Android 后置摄像头真实预览。
- 竖屏比例和方向正确。
- 横屏比例和方向正确。
- 非对称靶标四角映射正确。
- 触摸移动方向与画面方向一致。
- 前后台切换后状态正确。
- 断开/重连后预览和 ROI 仍然对齐。

### 10.4 AF/AE

- 支持的设备完成触发、收敛、锁定和状态确认。
- 不支持设备显示不支持，不显示成功。
- 请求失败显示失败原因。
- 锁定丢失时停止或阻止正式采集。
- 采集中不允许重新调优。

### 10.5 模型和端到端链路

- 安装包包含模型或可离线安装模型。
- 模型版本、配置和 SHA-256 可查询。
- 模型加载失败时阻止采集。
- 使用真实屏幕真值样本验证数字、小数点、亮度、反光、频闪和熄屏。
- 验证真实帧 → ROI → 推理 → 解析 → 入库 → 曲线 → 回放 → CSV。
- 失败、低置信度和无效输出不伪造数值。

### 10.6 性能和稳定性

- Android/Windows 均测试 1/3/5/8 ROI。
- 默认 1Hz 测试 P50/P95/P99 和丢帧率。
- 低性能配置测试明确选择的慢周期。
- 连续运行至少 4 小时。
- 检查 CPU、内存、温升、降频、断流、崩溃和数据完整性。
- 未测试组合不得加入支持清单。

### 10.7 安装包与验收记录

使用可交付构建，在 Android 真机断网安装/冷启动并加载模型；Windows 在干净的目标 Windows 10/11 x64 环境验证安装、断网启动、真实 UVC 取帧、导出及卸载。安装包必须携带所需运行库与模型资产，或通过受控离线安装流程提供。

每次正式验收必须记录：

- 构建版本和 APK/程序 SHA-256。
- 设备型号、系统版本和相机信息。
- 模型版本、运行库版本和 SHA-256。
- ROI 数量和采样周期。
- AF/AE 结果。
- 真值样本、输出结果和准确率。
- P95、丢帧率和连续运行结果。
- 失败项、复现步骤、日志和最终结论。
