# 问题点整理 2：实施与真机复测

适用构建：Android `0.4.2+6` 真机验证包，不作为正式性能放行。依据微信附件《问题点整理.md》五项正文。附件中的 66 条全失败是一个批次的现象，不是根因结论。

| 项目 | 实施 | 真机确认 |
|---|---|---|
| 01 更多 | 实时监控、历史回放统一为顶部导航栏右侧唯一入口。保留导出 CSV、失败日志、日志菜单。 | 两页均无需滚动即可打开，分别执行导出与日志查看。 |
| 02 识别失败 | 保留严格数字与置信度判定。诊断日志记录原始解码文本、失败原因、置信度、计划/帧时间、ROI 像素宽高、旋转、缩放宽度、亮度 P05/P95；开启失败快照后可导出保持比例的灰阶裁剪。 | 1000 ms，按 DEV01/02/03 对照实物真值，统计正确、错误、失败及丢拍。低置信度不当成功，失败不填假值。 |
| 03 画质与流畅度 | Android 后摄优先 1920×1080，系统选择相邻分辨率时会显示实际结果。预览直接渲染同一分析帧的完整视口像素，不再固定缩到长边 640；通过快速整数转换、原生线程和自适应节拍控制压力。相机声明支持时请求自动防闪烁。 | 对照旧版本记录预览、分析实际分辨率、预览提交 FPS 和 1000 ms 采样表现。独立验证清晰度、流畅度、屏闪；自动防闪烁不保证消除仪器自身的 PWM/扫描条纹。裁剪视口和设备分辨率回退均可使预览像素尺寸不同于分析输出。 |
| 04 取景调整 | 独立调整模式、同视口点按对焦标记、按设备能力显示竖向曝光补偿滑杆；独立显示 AE 状态。没有 AE 锁定的设备仍可调整曝光，但不能绕过正式采集的 AF/AE 门禁。 | 竖屏与横屏各点四角附近及仪表，验证标记与真实对焦一致；调亮/调暗后退出调整，重新框选 ROI 并检查锁定与亮度。 |
| 05 监控相机 | 曲线下方显示同一取景纹理、方向和 ROI 元数据。标签用当前采样轮的结果，失败/丢拍不显示上一轮读数；暂停时显示已暂停。 | 开始多个 ROI 的真实批次，检查画面、框、读数同步。遮挡单路仪表检查该路失败、不污染其他路。 |

## 建议复测步骤

1. 用同一手机、仪器、拍摄距离、光照、采样周期和 ROI 做 A/B 复测。先用“调整”点按仪器数字区域，调曝光避免暗屏或高光溢出，完成调整后仅框选数字与小数点。记录实际预览和分析分辨率、预览 FPS、相机型号及测试环境。页面 FPS 是预览提交速率，不是屏幕刷帧率。
2. 在“系统配置”启用失败快照（按现场数据管理要求选择），对每个 ROI 先用“测试选中 ROI（不入库）”核对原始文本、置信度，再开始采集。
3. 分设备同步记录仪器真值并导出普通 CSV 与失败日志。可用失败日志的 `frameAtMs`、`scheduledAtMs`、`device` 对齐结果和裁剪，判断是未输出字符、非完整数字、低置信度还是推理异常。保留至少一组典型成功与失败样本。只有真实数据达到已确认的验收指标，才能声称准确率、屏闪或性能达标。
