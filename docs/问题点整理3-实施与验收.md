# 问题点整理 3：实施与验收

适用：Android 0.4.3 真机验证构建。此轮不改动已保存的历史批次，也不把验证构建标为正式放行。

| 项目 | 实施与验证方法 |
| --- | --- |
| 预览 30 FPS | Camera2 支持 `[30,30]` 时请求固定档；不支持时显示相机实测预览帧率，不用重复帧表示达标。按相同手机、1080p 实际档位和样本，分别记录开启识别前/后的预览提交 FPS、采样周期及丢拍。预览和识别使用同一 CameraX 视口；GPU 转换 YUV，不再逐像素在 CPU 转换预览。 |
| 光学焦段 | 取景 → 调整 → 等效焦段。仅枚举 Android 暴露的独立后摄及可固定的物理后摄流；不调用数字变焦。未确认物理帧或绑定失败时退回原镜头。每个镜头分开保存本次编辑的 ROI 草稿，恢复草稿后必须确认对齐；首用焦段需重新画框。检查预览、实际裁剪、AF/AE、采样会话和批次的 `cameraId` 一致。 |
| 横竖屏趋势 | 随方向调整绘图区尺寸，继续使用原批次、轴向、时间范围和采集状态。采集中旋转手机，检查趋势不清空、坐标及图例可读、相机标记仍对齐。 |
| 新建批次 | 仅填有效且未被使用的批次编号；项目、人员留空。旧数据仍使用已有名称。 |
| 框选操作 | 移除「相机调优（ROI 优先）」和「测试选中 ROI（不入库）」入口；保留点按对焦、曝光补偿，以及启动时实际 AF/AE 锁定确认。 |

## 识别模型调整流程（待真实样本与候选模型）

1. 从真实手机采集仪表读数区域的原始彩色裁剪图，覆盖前导零、重复数字、小数点、不同设备、反光和闪烁；人工按当时显示的完整字符标注（例如 `003`，不是 `3`）。失败日志可定位相关帧，但不能只用失败样本代表总体。截图上的 `003 → 00` 只是一个误读例，不能据此补零或替换读数。
2. 按设备和批次隔离训练集、开发集、独立留出验证集，避免把同一次拍摄的近邻帧放到两边。候选模型必须有配套字典、配置和哈希；保留现有模型作为同条件基线。样本表使用 UTF-8 CSV，表头 `image,truth`，图片路径相对于该 CSV，不用会自动转换前导零的软件重存它。
3. 使用 `scripts/compare-rec.py` 在同一留出集评估（桌面 Python 安装 `onnxruntime`、`numpy`、`Pillow`）：

   ```powershell
   python scripts/compare-rec.py samples/heldout.csv --baseline android/app/src/main/assets --candidate samples/candidate --out comparison.csv
   ```

   不带 `--candidate` 可先跑基线。输出逐样本原文、置信度、失败/误读/完整匹配；另区分前导零等格式差异与实际数值错误，并报告自动接受准确率和覆盖率。桌面重采样与手机摄像管线并非逐像素等同，最终仍以手机真机的 A/B 复测为准。当前未收到带真值的实物裁剪集，保留随包现有离线 REC 权重，不报告识别率已提升。
